# v0.4 다중 망 구현 계획 (진행 기록 포함)

Spec: `docs/superpowers/specs/2026-10-29-multinet-design.md`
Branch: `v04-multinet` (~/netbridge). 검사 crate는 별도 worktree `../netbridge-wt-scan` 브랜치 `v04-scan` (서브에이전트).

## 단계
1. proto: NetId(=Side 별칭, transparent 문자열), Route, Topology, ThreatKind/Finding, RoutePolicy(+RoutePii, from_global, effective_pii, threat_action), TransferInfo.route/threats, Me.networks/routes, UserInfo/UserInput.networks, Hello.topology, ApiRequest Usage{to}/CreateTransfers{to}/Clipboard{to}, Admin ListRoutePolicies/SetRoutePolicy (ApprovalRules 제거). — 완료
2. server config: role hub/node, network, [[networks]] [[links]] [[routes]] [[neighbors]] [[scanners]], 기존 side= 설정 자동 변환.
3. server db 마이그레이션: transfers.direction→from_net/to_net, users.networks, route_policies 설정(JSON), 기존 approval_rules → 통로별로 이전.
4. core: peers: HashMap<NetId, Arc<dyn Peer>>, topology, route policy 조회/저장, 통로 검증, 통로별 한도·확장자·결재·PII·위협 조치, push/devices 다중 망, 세션 연동 전체 망.
5. link/relay: hub가 노드마다 링크, 노드 간 forward(PUT 이웃).
6. 테스트 갱신 (Side::Internal→NetId::internal()).
7. scan 통합 (서브에이전트 결과 merge, ThreatKind는 proto 것을 쓰도록).
8. client: Hello.topology, 받는 망 선택, 망 색, 통로 사용량, 클립보드 기본 대상, 관리자 통로 정책 탭, 사용자 망 선택.
9. 우클릭 전송 (NSIS 레지스트리 + --send + outbox).
10. 문서·버전 0.4.0, 빌드, 화면 확인, 릴리스.

## 기록
- 1~6단계 완료 (서버 테스트 88개 통과, multinet.rs 7개). 통로 정책 필드는 Option = 전역 상속.
- 7단계 완료: scan 통합 (위협 조치 max, CDR 시 크기·해시 갱신)
- 8단계 완료: 앱 다중 망 (전체 테스트 152개 통과)
- 9·10단계: 우클릭(--send+outbox, NSIS), 이웃 전용 수신 포트(ExpectFile), gen-certs --server, 0.4.0 빌드 OK, dev4 데모(B 중앙, A/C/D) 화면 확인. 최종 리뷰 진행 중
- 최종 리뷰: Important 2건(이웃 인증서로 중앙 연계 접속, 사용 망 축소 미반영) 수정·테스트. Minor 3,6(같은 망),7,8 수정. 연기: #4 CDR 후 크기 한도 재검사 없음, #5 Delivering 고착 재시도 없음, #6 이웃 설정 누락 사전 검사 없음
