# NetBridge — 사내 망연계 자료전송 시스템 설계

작성일: 2026-10-29
상태: 초안 (사용자 검토 전)

## 1. 목적과 배경

기존 상용 망연계 솔루션을 대체할 자체 자료전송 시스템을 만든다.

- 지금 가장 큰 불편은 **세션 끊김**이다. 인터넷망에서 로그인하면 업무망에도 함께 로그인되는데, 쓰는 도중에 연결이 끊긴다. 새 시스템은 **사용자가 로그아웃할 때까지 연결을 유지**해야 한다.
- 실제로 매일 쓰는 기능은 **파일 보내기**, **승인 결재**, **클립보드 복사** 세 가지다.
- 상용 제품은 리버싱하지 않는다(라이선스 약관 문제). 참고할 것은 공개 오픈소스뿐이다(9장).

## 2. 목표

1. 두 망(인터넷망 ↔ 업무망) 사이에 **양방향**으로 파일을 보낸다.
2. 파일 전송은 **사전결재**, **사후결재**, **대결** 세 방식으로 결재한다.
3. 클립보드 텍스트를 **단축키 하나**로 반대편 망 PC에 넘긴다. 기본 단축키는 ALT+F3이고, 사용자가 바꿀 수 있다. 클립보드는 결재하지 않는다.
4. 한쪽 망에서 로그인하면 양쪽 망 PC가 함께 로그인된다. 세션은 **로그아웃할 때만** 끝난다.
5. 관리자는 **하루 총 전송량**과 **파일 1개당 최대 크기**를 정한다.
6. 사용자 설정과 관리자 설정은 모두 **앱 화면**에서 바꾼다. 웹 화면은 만들지 않는다.
7. 배포는 Windows용 **exe 설치파일**로 한다.
8. 보내는 파일과 클립보드에서 **개인정보를 탐지**하고, 관리자가 정한 대로 기록하거나, 사전결재로 돌리거나, 차단한다.
9. 보안 규정과 인증 요건은 바뀔 수 있으므로, 규정에 걸리는 값은 모두 **관리자가 바꿀 수 있는 정책**으로 둔다.

## 3. 하지 않는 것 (1차 범위 밖)

- 자동승인, 다단계결재 (사용자가 범위에서 뺌)
- URL 연동, 메일 연동, 웹 관리자 화면
- 사내 AD 연동. 계정은 이 시스템 **전용 계정**을 쓴다(사용자 결정).
- 백신 검사와 파일 무해화(CDR)
- 이미지·파일 클립보드. 1차는 텍스트만 지원한다.
- 모바일, macOS 클라이언트

## 4. 절대 안 되는 것

- **중계 서버가 두 망을 네트워크 수준에서 이어 주는 것.** 서버는 패킷을 전달하지 않는다. 앱이 올린 파일과 텍스트만 정해진 절차로 넘긴다. 양쪽 수신 포트는 서로 다른 네트워크 인터페이스에 따로 묶는다.
- 사전결재 대상 파일이 승인 전에 반대편 망에서 보이는 것.
- 용량 한도를 클라이언트 쪽에서만 검사하는 것. 한도 판정은 반드시 서버가 한다.
- 로그아웃하지 않았는데 일시적인 네트워크 단절 때문에 세션이 끝나는 것.

## 5. 기술 결정

| 항목 | 결정 | 누가 정했나 |
|---|---|---|
| 클라이언트 형태 | 설치형 데스크톱 앱 (exe 설치파일) | 사용자 |
| 언어 | Rust | 사용자 |
| 앱 프레임워크 | eframe/egui 네이티브. WebView를 쓰지 않는다. | 사용자 |
| 한글 글꼴 | egui 기본 글꼴에는 한글이 없어서, OFL 라이선스 글꼴(Noto Sans KR 등)을 실행파일에 넣는다. | Claude |
| 설치파일 | NSIS로 만든 exe 설치파일. 시작 메뉴 등록, 시작 프로그램 등록, 제거 기능을 넣는다. | Claude |
| 연계 서버 | Rust (axum, tokio) 단일 실행파일. 같은 실행파일을 설정 파일의 역할값(`external` 또는 `internal`)에 따라 외부 연계서버나 내부 연계서버로 띄운다. | Claude |
| DB | SQLite 파일 1개. 사용자 수가 수백 명 수준이면 충분하다. | Claude |
| 파일 저장 | 서버 로컬 디스크 | Claude |
| 통신 | 앱 ↔ 서버 HTTPS + WebSocket. 사내 자체 인증서를 쓰고 앱에 인증서를 고정(pinning)한다. | Claude |
| 비밀번호 | argon2 해시 | Claude |

폐쇄망에서 빌드·배포하므로 Rust 의존성은 `cargo vendor`로 묶어 반입할 수 있어야 한다.

## 6. 전체 구조

```
[인터넷망 PC]           [외부 연계서버]  연계 구간  [내부 연계서버]          [업무망 PC]
 NetBridge 앱 ─HTTPS/WS─▶   (인터넷망)  ◀─mTLS 전용─▶   (업무망)   ◀─HTTPS/WS─ NetBridge 앱
                          SQLite+파일                 SQLite+파일
```

- 사용자는 "기존 솔루션 구성을 따르면 된다"고 했다. 기존 솔루션의 정확한 구성도는 공개 자료로 확인하지 못했다. 그래서 국내 망연계 제품의 일반적인 구성을 따라 **망마다 연계서버를 한 대씩 두고, 두 서버만 전용 연계 구간으로 잇는다**(Claude 결정). 이 구성은 서버 한 대에 두 망을 함께 꽂는 방식보다 규정 요건에 걸릴 위험이 작다.
- 각 PC의 앱은 **자기 망의 연계서버에만** 접속한다. 반대편 망 주소는 알지 못한다.
- 연계 구간은 서로 인증하는 TLS(mTLS) 하나만 쓴다. 이 구간에서 오가는 것은 정해진 메시지 종류뿐이다(세션 알림, 결재 결과, 파일 조각, 클립보드 텍스트, 정책 동기화).
- **기준 데이터**(계정, 정책, 결재, 이력)는 내부 연계서버가 가진다. 외부 연계서버는 필요한 사본만 받는다(Claude 결정). 관리자 화면은 업무망 앱에서만 열린다.
- 개발과 시험은 한 PC에서 두 서버를 서로 다른 포트로 띄워 흉내 낸다. 실제 배치는 설정 파일의 주소만 바꾼다.
- 앱은 하나다. 설치할 때(또는 첫 실행 때) 어느 망 PC인지와 서버 주소를 설정한다.
- 앱은 시스템 트레이에 상주한다. 창을 닫아도 트레이에 남아 있다.

## 7. 기능 상세

### 7.1 계정과 기기

- 계정은 관리자가 앱의 관리자 화면에서 만든다. 항목은 아이디, 이름, 부서, 역할, 결재자다.
- 역할은 `사용자`와 `관리자` 두 가지다. 결재자는 따로 역할을 두지 않는다. 사용자마다 "내 결재자"를 지정한다(기본값은 소속 부서장, Claude 가정).
- 로그인 5회 실패 시 계정을 잠그고, 관리자가 해제한다. 비밀번호는 사용자가 직접 바꿀 수 있다.
- **기기 등록**: 사용자의 인터넷망 PC와 업무망 PC를 한 쌍으로 묶는다. 처음 로그인한 PC가 자동으로 등록되고, 바꾸려면 관리자가 해제한다(Claude 결정). 양쪽 동시 로그인은 이 쌍을 기준으로 한다.
- **기기 인증**: 기기를 등록할 때 서버가 기기 키를 발급하고, 앱은 이 키를 Windows DPAPI로 암호화해 저장한다. 반대편 PC 앱은 사용자 로그인 전에도 이 기기 키로 서버에 붙어 대기한다. 사용자 비밀번호는 PC에 저장하지 않는다(Claude 결정).

### 7.2 세션 유지 (핵심)

1. 사용자가 어느 한쪽 앱에서 로그인하면, 서버는 그 사용자의 세션을 만들고 반대편에 등록된 PC의 앱에도 WebSocket으로 "로그인됨"을 알린다. 반대편 앱은 이미 서버에 연결되어 대기 중이다.
2. 앱은 30초마다 서버에 신호(heartbeat)를 보낸다.
3. 네트워크가 끊기면 앱은 1초, 2초, 4초 … 최대 30초 간격으로 계속 재연결한다. **재연결은 세션을 끝내지 않는다.** 서버 쪽 세션도 그대로 남는다.
4. 세션은 다음 경우에만 끝난다.
   - 사용자가 어느 한쪽에서 로그아웃 → 양쪽 모두 로그아웃
   - 관리자가 강제 종료
   - 관리자가 정한 **최대 유지 시간** 초과. PC를 켜 둔 채 퇴근하는 경우를 대비한 값이다. 기본값은 "제한 없음"이다(Claude 가정).
5. 한쪽 PC만 재부팅되면 그 PC에서 다시 로그인해야 한다. 다시 로그인하면 기존 세션에 다시 붙고, 반대편 PC는 계속 로그인 상태로 남는다(Claude 결정).
6. 세션 최대 유지 시간과 미사용 시 화면 잠금 시간은 7.9의 보안정책 값이다. 규정이 바뀌면 관리자가 값만 바꾼다.

### 7.3 파일 보내기

1. 사용자가 파일을 앱으로 끌어다 놓거나 선택한다. 여러 개를 한 번에 보낼 수 있다.
2. 앱이 SHA-256 해시를 계산하고 서버에 나눠서 올린다(청크 업로드). 끊기면 이어서 올린다.
3. 서버가 한도를 검사한다(7.5). 넘으면 거부하고 이유를 보여 준다.
4. 서버가 결재 방식을 정하고(7.4) 그에 따라 반대편에 공개한다.
5. 반대편 앱의 "받은 파일" 목록에 나타나면, 사용자가 받기를 눌러 원하는 폴더에 저장한다. 받은 뒤 해시를 확인한다.
6. 받은 파일은 서버에서 보관 기간(관리자 설정, 기본 7일) 뒤 지운다. 메타데이터와 이력은 남긴다.

### 7.4 결재

결재 방식은 세 가지다.

- **사전결재**: 결재자가 승인해야 반대편에 공개한다. 반려하면 공개하지 않고, 보낸 사람에게 사유와 함께 알린다.
- **사후결재**: 바로 반대편에 공개하고, 결재 요청은 결재함에 쌓인다. 결재 기한(관리자 설정, 기본 3일, 주말 포함 역일 기준)을 넘기면 관리자에게 알리고, 그 사용자는 미결 건이 정리될 때까지 사후결재 대상 전송이 막히고 사전결재로만 보낼 수 있다(Claude 제안, 사용자 이의 없음). 사후 반려는 이미 넘어간 파일을 되돌릴 수 없으므로 반려 기록과 관리자 알림만 남긴다.
- **대결**: 결재자가 앱에서 대리인과 기간을 지정한다. 그 기간에는 대리인도 결재할 수 있고, 이력에는 "대결" 표시와 대리인 이름이 남는다.

**적용 규칙**: 관리자가 규칙 목록을 만든다. 조건은 전송 방향, 파일 크기, 확장자, 부서이고, 결과는 사전결재 또는 사후결재다. 위에서부터 처음 맞는 규칙을 적용하고, 맞는 규칙이 없으면 **사전결재**로 처리한다.

결재자는 앱의 결재함에서 파일명, 크기, 해시, 보낸 사람, 사유, 개인정보 탐지 결과(7.8)를 보고 승인하거나 반려한다. 보낼 때 사유는 선택이다. 다만 개인정보 탐지로 사전결재가 강제된 파일은 "사유 입력 필요" 상태로 멈추고, 보낸 사람이 사유를 적어 결재를 요청해야 결재자에게 올라간다(사용자 결정, 2026-10-29). 결재함은 양쪽 망 앱 어디서나 열린다. 다만 사전결재 파일의 **내용 열람은 보내는 쪽 망 앱에서만** 할 수 있다. 승인 전에 받는 쪽 망에 내용이 넘어가면 안 되기 때문이다(Claude 결정).

### 7.5 용량 한도

- 한도 두 가지: **하루 총 전송량**, **파일 1개 최대 크기**
- 단위: 전사 기본값 → 부서 → 개인. 가장 구체적인 값이 적용된다.
- 하루 기준은 한국 시간 자정에 초기화한다. 반려된 파일은 사용량에서 뺀다(Claude 결정).
- 클립보드 텍스트는 한 번에 보낼 수 있는 최대 글자 수를 따로 둔다(기본 100KB, Claude 가정). 하루 총량에는 넣지 않는다.

### 7.6 클립보드

1. 사용자가 텍스트를 복사하고 단축키(기본 ALT+F3)를 누른다.
2. 앱이 클립보드 텍스트를 읽어 서버로 보낸다. 서버는 반대편에 등록된 PC의 앱으로 바로 넘긴다.
3. 반대편 앱이 클립보드에 넣고 트레이 알림을 띄운다.
4. 반대편 PC가 연결되어 있지 않으면 실패를 알린다. 저장해 두었다가 나중에 보내지 않는다.
5. 단축키는 사용자 설정 화면에서 바꾼다. 다른 프로그램이 이미 쓰는 단축키면 등록 실패를 알린다.

### 7.7 이력과 감사

- 남기는 것: 로그인과 로그아웃, 파일 전송(파일명, 크기, 해시, 방향, 결재 결과, 결재자), 결재 행위, 관리자 설정 변경, 클립보드 전송
- 클립보드는 내용을 이력에 남기되, **탐지된 개인정보는 가린 상태로** 저장한다. 예를 들어 `900101-1******`처럼 남긴다(Claude 결정).
- 관리자는 앱에서 기간, 사용자, 종류로 이력을 검색하고 CSV로 내보낸다.
- 모든 전송 이력에는 **송신 IP와 수신 IP**를 남기고 화면에 보여 준다. 송신 IP는 보낸 PC, 수신 IP는 받은 PC의 주소다. 기존 솔루션에도 같은 정보가 나온다(사용자 의견). 앱 하단 상태줄에는 내 PC IP, 접속 서버 주소, 연결 상태를 보여 준다.
- 이력 보관 기간은 7.9의 보안정책 값이다. 기간이 지난 이력은 자동으로 지운다.

### 7.8 개인정보 탐지

- **검사 대상**: 보내는 파일과 클립보드 텍스트. 파일은 텍스트 계열(txt, csv, log, json, xml, html)과 문서(docx, xlsx, pptx, hwpx, pdf)에서 글자를 뽑아 검사한다. 글자를 뽑을 수 없는 형식(이미지, 압축, 구형 hwp 등)은 "검사 불가"로 표시한다(Claude 결정).
- **검사 위치**: 보내는 쪽 연계서버. 앱에서 검사하면 우회할 수 있기 때문이다.
- **기본 탐지 항목**: 주민등록번호와 외국인등록번호(검증 숫자 확인), 휴대전화번호, 신용카드번호(Luhn 검사), 계좌번호, 여권번호, 운전면허번호, 이메일 주소
- **관리자 설정**: 항목마다 켜고 끌 수 있다. 관리자가 정규식으로 새 항목을 추가할 수 있다. 항목마다 몇 건 이상일 때 조치할지 정한다.
- **조치**(항목별로 관리자가 고름)
  - `기록만`: 전송하고 탐지 결과만 이력에 남긴다.
  - `사전결재 강제`: 결재 규칙과 상관없이 사전결재로 처리하고, 결재자에게 탐지 결과를 보여 준다.
  - `차단`: 보내지 않고, 보낸 사람에게 어떤 항목이 몇 건 나왔는지 알린다.
  - `검사 불가` 파일에 어떤 조치를 할지도 관리자가 정한다. 기본값은 `사전결재 강제`다.
- 클립보드는 결재가 없으므로 `사전결재 강제`는 `차단`으로 처리한다(Claude 결정).

### 7.9 보안정책 관리

규정과 인증 요건은 언제든 바뀔 수 있다(사용자 의견). 그래서 규정에 걸리는 값은 코드에 박아 두지 않는다. 모두 관리자 화면의 **보안정책** 항목으로 두고, 바꾸면 양쪽 서버와 접속 중인 앱에 바로 반영한다.

| 정책 | 기본값 (Claude 가정) |
|---|---|
| 세션 최대 유지 시간 | 제한 없음 |
| 미사용 시 앱 화면 잠금 | 사용 안 함 |
| 비밀번호 최소 길이, 조합 규칙, 변경 주기 | 9자 이상, 영문·숫자·특수문자 조합, 90일 |
| 로그인 실패 잠금 횟수 | 5회 |
| 전송 허용·차단 확장자 목록 | 차단: exe, dll, bat, cmd, ps1, vbs, js, msi |
| 파일 보관 기간 | 7일 |
| 이력 보관 기간 | 1년 |
| 사후결재 기한 | 3일 |
| 개인정보 탐지 항목과 조치 | 7.8 참고 |
| 용량 한도 | 7.5 참고 |

- 정책을 바꾼 기록(누가, 언제, 이전 값, 새 값)은 이력에 남긴다.
- 관리자는 정책 전체를 파일로 내보내고 가져올 수 있다. 규정 변경에 맞춰 미리 만든 정책을 한 번에 적용하는 용도다.

## 8. 화면 목록

**사용자**: 로그인, 파일 보내기, 받은 파일, 내 전송 이력, 결재함(결재자일 때), 대결 지정, 설정(단축키, 비밀번호, 기본 저장 폴더)

**관리자**(업무망 앱에서 관리자 계정일 때 추가): 계정·부서 관리, 기기 등록 해제, 용량 한도, 결재 규칙, 보안정책(7.9), 개인정보 탐지 설정(7.8), 이력 조회, 접속 중 세션 목록과 강제 종료

## 9. 참고 자료와 남은 일

### 9.1 참고 오픈소스 (소스코드를 읽고 분석)

- ANSSI lidi (Rust, LGPL-3.0): 일방향 전송, 오류정정, 청크 처리
- cea-sec hairgap: 일방향 전송 도구 모음
- pydiode: 단순한 구조 참고

이들은 일방향 다이오드용이라 결재와 세션 기능은 없다. 청크 전송, 무결성 검사, 재전송 설계만 참고하고 코드는 가져오지 않는다(라이선스 섞임 방지).

### 9.2 배포 전에 현장에서 확인할 것

- 실제 물리 망 구성. 연계 구간을 어떤 회선이나 장비로 잇는지 확인해야 한다.
- 업무망 PC의 백신, DLP, EDR이 전역 단축키, 클립보드 접근, 설치파일 실행을 막는지. 개발 첫 단계에 실제 PC에서 시험한다.
- 사내 코드서명 인증서가 있는지. 없으면 서명 없는 설치파일이 차단될 수 있다.
- 기존 솔루션 데이터(계정, 이력)는 옮기지 않는다. 계정은 새로 만든다(Claude 결정).

### 9.3 만드는 사람이 정할 것

- 크레이트 선택, DB 스키마, API 모양, 화면 배치와 디자인
- 서버를 Windows 서비스와 Linux systemd 중 어느 형태로 우선 제공할지. 두 가지 모두 빌드할 수 있어야 한다.
- 테스트 구성. 서버 한 대와 두 망을 흉내 내는 로컬 환경에서 끝까지 도는 테스트가 있어야 한다.
