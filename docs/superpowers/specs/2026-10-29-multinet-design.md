# NetBridge 다중 망 · 통로별 정책 · 파일 검사 · 우클릭 전송 설계 (v0.4)

## 왜

현장에는 망이 둘이 아니라 여럿이다. 예: A·B·C·D 네 망에서 허용된 통로는 A↔B, B↔C, B↔D, C↔D뿐이다.
A에서 C로 바로 보낼 수 없다. 통로마다, 그리고 방향마다 규정이 다르다. 예를 들어 A→B로 들여오는 파일은 엄격하게 검사하고, B→A로 내보낼 때는 개인정보를 중심으로 본다.
또 사용자는 탐색기에서 파일을 우클릭해 바로 보내고 싶어 하고, 들어오는 파일의 악성 여부를 검사하고 싶어 한다.

## 사용자가 정한 것 (2026-10-29)

- 중앙 관리 서버(계정·결재·정책·감사 DB)는 **B망 서버**에 둔다. B망은 다른 모든 망과 직접 연결되어 있다.
- 로그인 연동: 한 망에서 로그인하면 그 사용자에게 **허용된 모든 망** PC가 함께 로그인·로그아웃된다.
- 통로 정책은 **방향별로 따로** 둔다(A→B ≠ B→A). "반대 방향과 같게" 복사 버튼을 둔다.
- 파일 검사: **내장 검사 + 외부 백신/CDR 연동**. 검사 결과에 따른 조치는 통로 정책에서 정한다.
- (이전 결정 유지) 상용 망연계 제품은 리버싱하지 않는다. 공개 자료만 참고한다.

## 목표 / 비목표

목표
1. 망 N개, 통로는 망 쌍 단위로 설정한다. 허용되지 않은 방향의 전송·클립보드는 서버가 거부한다.
2. 방향별 통로 정책은 다음을 포함한다: 사용 여부, 클립보드 허용, 하루·파일 한도, 차단/허용 확장자, 결재 규칙, 개인정보 항목별 조치, 검사 불가 조치, 위협 유형별 조치.
3. 파일은 **통로를 따라서만** 이동한다. C→D 파일은 C 서버에서 D 서버로 바로 간다. 중앙(B) 서버를 거치지 않는다.
4. 내장 파일 검사: 실행파일 위장, 스크립트, 문서 매크로(OOXML·OLE·HWP 스크립트), PDF 스크립트·실행 동작, 압축 안의 위험 파일·암호 압축·압축 폭탄. 여기에 외부 명령 연동(백신 검사 결과, CDR 무해화 결과 파일 교체)을 더한다.
5. 탐색기 우클릭 메뉴 "NetBridge로 자료전송": 실행 중인 앱에 파일을 넘기고, 보낼 망을 고르게 한다.
6. 기존 2망(내부·외부) 설정 파일과 DB는 그대로 동작한다(자동 변환).

비목표
- 여러 통로를 거치는 전송(A→B→C). 사용자가 원하지 않았고 망 분리 원칙에 어긋난다.
- 망 구성을 관리자 화면에서 바꾸는 것. 망·통로·주소는 물리 구성이라 서버 설정 파일이 기준이다. 관리자 화면은 통로 **정책**만 바꾼다.
- 자체 백신 엔진, 자체 CDR. 이 둘은 상용 제품을 연동한다.

## 구성

### 망과 서버
- 망마다 연계서버가 하나씩 있다. 서버 설정의 `network = "B"`가 자기 망이다.
- 중앙 서버(`role = "hub"`, B)에만 DB가 있다. 나머지 서버(`role = "node"`)는 지금의 외부 서버처럼 동작한다. API는 중앙으로 중계하고, 파일은 자기 디스크에 보관한다.
- 중앙 서버 설정에 망 목록과 통로 목록이 있다.
  ```toml
  role = "hub"
  network = "B"
  [[networks]]           # 이름·색은 앱 표시용
  id = "A"; name = "A망(인터넷)"
  [[networks]]
  id = "B"; name = "B망(업무)"
  ...
  [[links]]              # 중앙과 직접 연결된 망: 중앙이 먼저 접속 (지금과 같은 mTLS WS + HTTPS)
  network = "A"; url = "https://a-link:19443"
  [[routes]]             # 허용된 통로 (양방향 쌍). C-D처럼 중앙이 끼지 않은 통로도 여기 적는다
  a = "A"; b = "B"
  a = "C"; b = "D"
  ```
- 중앙이 아닌 서버끼리의 통로(C-D)를 위해 노드 설정에 `[[neighbors]] network = "D"; url = "https://d-link:19443"`를 둔다. C 서버는 D 서버의 연계 수신 주소로 파일을 직접 올린다(PUT /link/files/:id, mTLS). 그래서 노드의 연계 수신 주소는 중앙과 이웃 노드 모두에게서 접속을 받는다.
- 시작할 때 중앙 서버는 모든 노드가 `[[links]]`에 있는지 확인한다(중앙과 직접 연결되지 않은 망은 거부). 노드는 자기가 속한 비중앙 통로마다 `[[neighbors]]` 주소가 있는지 확인한다. 이 확인은 중앙이 내려주는 통로 목록으로 연결 시점에 한다.
- **호환**: `side = "internal"` 설정은 hub/network "internal"(업무망)로 바꿔 읽는다. 망은 internal·external 둘, 통로는 internal-external, 링크는 `external_url`이다. `side = "external"` 설정은 node/network "external"로 바꿔 읽는다.

### 식별자
- `Side` enum을 망 ID(`NetId`, 문자열 newtype)로 바꾼다. `Direction`은 `Route { from: NetId, to: NetId }`로 바꾼다.
- DB: `transfers.direction` → `from_net`, `to_net`. `devices.side` → 망 ID 문자열. 기존 값 'ToInternal'은 external→internal로, 'Internal'은 'internal'로 바꾼다. 이 변환은 시작할 때 자동으로 한다.

### 사용자와 로그인
- 사용자마다 쓸 수 있는 망 목록(`users.networks`, 비어 있으면 전체)을 둔다. 관리자 화면에서 고른다.
- 로그인은 아무 허용 망에서나 할 수 있다. 성공하면 그 사용자의 다른 모든 허용 망 기기에 SessionStarted를 보낸다. 로그아웃·세션 종료도 모든 망에 보낸다.
- 관리자 콘솔은 중앙 망 PC에서 관리자 계정으로만 열린다(지금과 같은 원칙).

### 통로 정책
- `RoutePolicy { from, to, enabled, clipboard, limits, blocked_exts, allowed_exts, approval_rules, pii_actions: Vec<(rule_id, threshold, action)>, unscannable_action, threat_actions: {executable, script, macro, pdf_active, archive_danger, encrypted, av_infected, scanner_error} }`.
- 전역 `Policy`에는 계정·세션·비밀번호·보관 기간·사후결재 기한·클립보드 최대 크기·개인정보 **탐지 규칙 정의**(정규식 등)가 남는다. 통로 정책은 "어느 항목이 몇 건이면 어떤 조치"만 가진다.
- 통로 정책이 아직 없는 방향은 전역 기본값에서 만든다(기존 기본 한도·확장자·결재 규칙·개인정보 조치를 그대로 씀). 그래서 기존 설치는 업그레이드해도 동작이 같다.
- 한도: 하루 사용량은 **방향별로** 센다. 부서·개인 예외 한도는 통로를 지정하거나, "모든 통로"로 둘 수 있다.
- 통로 정책을 저장하면 해당 두 망의 접속 PC에 바로 반영된다(PolicyChanged에 통로 정책 포함).

### 파일 이동
- 전송 생성: 보내는 망(내가 접속한 망) → 받는 망(사용자가 고름). 통로가 없거나 꺼져 있으면 거부한다.
- 검사: 파일이 있는 서버에서 한다. 중앙 망의 파일이면 중앙에서, 노드 망의 파일이면 그 노드에서 한다. 중앙은 결과만 받는다. 지금 구조와 같다.
- 전달:
  - from=중앙 → to 노드: 중앙이 노드로 push한다(지금과 같음).
  - from 노드 → to=중앙: 중앙이 노드에서 fetch한다(지금과 같음).
  - from 노드 → to 노드: 중앙이 from 노드에 "to 망으로 보내라"(POST /link/forward)를 지시한다. from 노드가 이웃 연결로 to 노드에 PUT한다. 해시는 받는 쪽에서 확인한다.
- 받은 파일 다운로드와 송신측 사본 삭제는 지금 규칙을 그대로 쓴다.

### 파일 검사 (`crates/scan`)
- 내장 검사는 내용 기준이다(확장자를 믿지 않는다). 찾는 항목:
  - PE/ELF/Mach-O 실행파일
  - 스크립트: bat, cmd, ps1, vbs, js, jse, wsf, hta, lnk, scr 등 + 셔뱅
  - OOXML 매크로: vbaProject.bin, docm/xlsm/pptm
  - OLE 매크로: `_VBA_PROJECT`, `Macros`
  - HWP 스크립트: `DefaultJScript`, `Scripts`
  - PDF 동작: `/JavaScript`, `/JS`, `/Launch`, `/EmbeddedFile`, `/OpenAction`+JS
  - 압축(zip): 안의 파일 이름과 내용을 다시 검사(최대 깊이 3). 암호 항목, 압축 폭탄(풀린 크기 합 > 1 GiB 또는 비율 > 100배), 항목 수 > 10,000.
- 결과는 `Finding { kind, detail }` 목록이다. `kind` ∈ {Executable, Script, Macro, PdfActive, ArchiveDanger, Encrypted, AvInfected, ScannerError}.
- 외부 연동(망별 서버 설정 `[[scanners]]`):
  - `command = ["C:/AV/scan.exe", "{file}"]`, `infected_exit_codes = [1]`, `timeout_secs`
  - CDR은 `cdr_command = ["cdr.exe", "{file}", "{out}"]`. 성공하면 결과 파일로 바꾸고 해시를 다시 계산한다. 실패하면 ScannerError로 처리한다.
  - 연동 설정은 그 망 서버의 설정 파일에 둔다. 검사 명령의 경로는 서버마다 다르기 때문이다.
- 조치: 통로 정책 `threat_actions[kind]` ∈ {Block, ForcePre, LogOnly}. 기본값은 다음과 같다.
  - 실행파일·스크립트: 차단 (확장자 정책과 별개로 내용 기준)
  - 매크로: 사전결재
  - PDF 동작: 사전결재
  - 압축 위험: 차단
  - 암호: 사전결재
  - 백신 탐지: 차단
  - 검사기 오류: 사전결재
- 감사 기록과 결재 화면에 탐지 내용을 보여 준다.

### 앱
- 접속한 망이 `Hello`/`Me`로 망 목록, 내 망, 보낼 수 있는 망(통로 정책 enabled 기준)을 받는다.
- 파일 보내기: "받는 망" 선택 칸이 있다(하나면 고정 표시). 사용량 카드는 고른 통로 기준이다.
- 받은 파일·보낸 파일 목록에 보낸 망 → 받은 망을 표시한다.
- 클립보드 단축키는 PC별 "클립보드 기본 대상 망"(설정)으로 보낸다. 대상이 하나면 자동으로 정해진다.
- 망 색: 망 목록 순서대로 정해진 팔레트를 쓴다.
- 우클릭 전송:
  - 설치파일이 `HKLM\Software\Classes\*\shell\NetBridgeSend`("NetBridge로 자료전송", 아이콘)를 등록하고, 명령은 `"…\netbridge.exe" --send "%1"`로 한다.
  - 앱은 `--send` 경로를 `%LOCALAPPDATA%\NetBridge\outbox\<uuid>.txt`에 쓰고 실행 중인 창을 깨운다(이미 있는 이름 있는 이벤트).
  - 실행 중이 아니면 자기가 창을 열고 같은 outbox를 읽는다.
  - 창은 outbox를 읽어 파일 보내기 화면에 추가하고 앞으로 나온다. 로그인 전이면 로그인 뒤에 추가한다.
  - 여러 파일을 고르면 파일마다 프로세스가 뜨지만, 모두 outbox로 모인다.
- 관리자 콘솔: "통로 정책" 탭을 추가한다. 통로 목록(from→to)에서 하나를 고르면 정책을 편집한다. "반대 방향과 같게" 복사를 둔다. 사용자 편집에 "사용 망" 선택을 추가한다.

## 판단은 구현자에게
- 위협 기본 조치 외 세부 값(압축 깊이·비율)은 위 숫자를 쓰되 상수로 둔다.
- 망 색 팔레트, 화면 배치 세부.
